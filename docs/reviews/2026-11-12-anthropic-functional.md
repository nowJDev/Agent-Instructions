# Anthropic 스킬 실제 작업 검증과 GitHub 배포.

사용자는 설치 완료 뒤 남아 있던 개별 스킬의 실제 작업 검증과 GitHub push를 추가 요청했다. [실행 계획](../superpowers/plans/2026-11-12-anthropic-functional.md)에 따라 기존 설치 검증의 후속 범위로 수행한다. [이전 기록](2026-11-12-anthropic-skills.md)은 파일 배치·중복 조사·프로세스 발견까지의 당시 증거다.

## 검증 계약.

19개 설치본의 SKILL.md와 필요한 참조를 실제 읽고 합성 입력을 사용해 문서·이미지·웹·SDK·MCP·스킬 평가·문장 작업을 수행한다. 공개 저장소에는 검증 요약만 두고 원문 로그·생성 산출물·격리 종속성은 사용자 로컬 검증 폴더에 보관한다. 개인 정보·API 키·기존 회사 자료는 사용하지 않는다. 실제 파일이나 동작이 없는 import·구문·경로 검사만으로 통과를 선언하지 않는다.

아래 판정은 작은 합성 샘플에서 확인한 범위다. 스킬의 모든 기능·자동 선택 품질·임의의 사용자 입력에서 성공한다는 보장은 아니다. 원본 스크립트의 실패, 대체 실행 경로, 실제 외부 서비스 인증과 모델 호출은 구분한다.

집계는 대표 샘플 통과 13개, 조건부 5개, 환경 제한으로 번들 실패 1개다. 색상·폰트 선언처럼 표에서 범위를 제한한 통과를 전체 Office 렌더 성공으로 확대하지 않는다. 원본 스킬 전체의 모든 기능이 정상이라는 판정도 아니다.

## 확인한 환경과 제한.

- Python 3.11.9·3.12.10과 Node를 재사용했다. 필요한 SDK·라이브러리는 검증용 작업 폴더 안에만 설치했다. 전역 스킬 원문·개인 설정·권한을 추가로 변경하지 않았다.
- API SDK는 루프백 HTTP 서버로 실제 요청과 오류 처리를 검사한다. 유료 Anthropic 모델 호출·실제 인증은 수행하지 않는다.
- 사용자 기존 Office·브라우저·서버를 종료하지 않는다. 검증에서 생성한 인스턴스와 서버만 종료한다.
- 문장 스킬은 완결된 합성 브리프와 피드백을 입력으로 사용한다. 사람의 실제 승인 대화나 사용자 업무 보고로 가장하지 않는다.

원본 Office `soffice.py`와 스프레드시트 `recalc.py`는 Windows Python에서 `socket.AF_UNIX` 부재로 실제 실패했다. 새 Word COM 인스턴스도 응답하지 않아 시간 제한 후 해당 worker와 생성 시각으로 확인한 새 Word만 종료했다. Excel·PowerPoint COM 단계는 실행되지 않았다. 사용자 기존 Office는 종료하지 않았다. 이 실패를 파일 형식 검증이나 독립 수치 검산으로 대체해 성공 처리하지 않는다.

개발 스킬의 원본 Python 참고 예제는 SDK v1 FastMCP 형태였으나 격리 설치한 현재 MCP 2.3.0에서는 공식 v2 MCPServer/Client 계약을 확인해 샘플을 작성했다. 로컬 API stub의 응답은 합성 데이터이며 실제 Anthropic의 모델 유효성·응답 품질·서비스 오류 정책을 검증한 것이 아니다.

문서 산출물 11개와 시각·웹 산출물 29개의 해시는 주 에이전트가 별도 대조했다. 검증용 포트 8767·8773·8775는 최종 TCP 연결 검사에서 모두 닫혔다. 원본 with_server.py는 Windows에서 shell 프로세스만 종료해 자식 서버가 남는 동작을 보였다. 이 자동 정리 실패와 별도로 수행한 소유 서버 정리 성공을 구분한다. 웹 아티팩트 init은 버전이 고정되지 않아 React 19·Vite 8·TypeScript 7을 선택했으며, 스킬에 적힌 React 18 기준과 다르다는 점도 남긴다.

## 공개와 배포.

독립 리뷰에서 19개 명세와 표의 누락·중복 0개, 13·5·1 집계와 원문 증거의 일치를 확인했다. PNG와 PDF의 시각 검사 범위를 구분하도록 경미한 표현 1개를 보완했다. Windows Python 3.12의 전체 회귀 103개와 공개 문서 링크·diff 검사를 통과했다.

사용자는 이번 후속 요청에서 GitHub push를 승인했다. 원격보다 앞선 기존 main의 미푸시 4개 커밋에는 이전 Unity MCP 작업 2개와 Anthropic 설치 작업 2개가 포함돼 있다. 기존 이력을 보존해 후속 검증 기록과 함께 일반 push하며 force push를 사용하지 않는다. 공개 대상 21개 기존 변경 파일의 시크릿·개인 절대 경로 검사를 통과했고 `git push --dry-run origin main`으로 인증과 fast-forward 가능성을 확인했다. 실제 push·원격 SHA·CI 결과는 후속 증거로 확정한다.
