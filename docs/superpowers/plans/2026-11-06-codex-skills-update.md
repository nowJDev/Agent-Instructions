# Codex 전용 스킬 업데이트 실행 계획.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 승인된 원본으로 Codex 스킬의 필요한 패키지를 갱신하고 이름 전환·퇴역·보류와 보존 검증을 기록한다.

**Architecture:** 기존 전역 패키지 구조를 재사용한다. 준비 묶음 A 32개와 B 25개를 전체 파일 manifest로 대조하고 동일 패키지는 유지하며, 공개 저장소에는 문서와 검증 결과만 남긴다.

**Tech Stack:** Markdown, Git, Python 3.12 표준 라이브러리, PowerShell, 설치된 Codex 읽기 전용 조회 기능.

**Spec:** [승인 설계](../specs/2026-11-06-codex-skills-update.md).

## 공통 경계.

- 사용자 “설계안대로 진행” 승인 이후의 Codex-only 제한을 따른다. Claude 설치본·설정·캐시, 클라이언트 설정·인증·CLI는 변경하지 않는다.
- 기준선은 `13e3566ada503dfb1badec39c5bb79c554dff36e`다. 별도 worktree의 사용자 변경과 원본 작업 경로를 보존한다.
- 전역 103개 중 후보 57개·퇴역 1개·유지 45개다. 후보 수를 실질 변경 수로 보고하지 않는다. 정상 결과는 전역 102개, 별도 6개와 앱 세션 플러그인 24개를 포함한 출처 관리 132개다. 실제 사용자 새 CLI 발견은 적용 전 123개·적용 후 122개가 기대되며 CLI 플러그인 노출은 14개다.
- 준비 묶음의 승인 원본·버전은 설계 표를 따른다. 최신 HEAD, 번들 버전, 개별 선언, 실제 서버·CLI 버전을 서로 대신하지 않는다.
- Qodo 2개와 버전 선택이 불가능한 네이티브 관리 항목은 보류한다. 관리 캐시를 수동 수정하거나 새 플러그인·스킬·MCP를 임의 추가하지 않는다. 공개 원본이 있어도 browser/chrome의 빈 skills 캐시를 복구하지 않는다.
- 원시 manifest·개인 절대경로·설정·복구 자료·타사 실행 원문은 공개하지 않는다. 기존 개인 참조·알 수 없는 파일·데이터 전송 검증을 보존한다.

## 검토 초점.

- 조사 후 파일 변경이나 링크 경계 이탈은 덮어쓰기 대신 적용 중단으로 처리한다. Task 1의 해시·경계 검사가 이를 확인한다.
- 후보와 동일 패키지를 구분하고 보존 파일을 버리지 않는다. Task 2에서 전체 패키지·패치·제거 후보를 대조한다.
- `firecrawl-cli` 전환 중 실패하면 구형 기능이 유실되거나 두 이름이 활성화되지 않게 한다. Task 2의 성공·복구 검사가 이를 확인한다.
- 새 런타임 기능을 스킬 파일 교체로 제공했다고 보고하지 않는다. Task 3에서 발견·읽기와 실제 외부 실행을 구분한다.
- 다른 계정의 발견 목록과 오래된 세션 캐시를 사용하지 않는다. Task 3에서 실제 사용자 계정·경로·전역 102개와 새 CLI 전체 122개 기대 목록을 대조한다. 앱 세션 24개와 새 CLI 14개의 플러그인 노출 차이는 상태 오류로 단정하지 않는다.

배치·로컬 검증과 전체 회귀·최종 독립 리뷰를 수행한 기록이다. 후보 57개 중 실제 변경 48개·동일 유지 9개이며 Git 반영 결과는 별도로 확인한다.

### Task 1. 기준선·원본·보존 자료를 확정한다.

**Files:** 공개 저장소 밖의 `stage-a/manifest.json`, `stage-b/manifest.json`, 현재 설치·보호 파일 manifest와 비공개 복구 자료를 사용한다. 실제 작업 디렉터리는 실행자가 로컬 기록으로 관리한다.

**Interfaces:** 준비 manifest는 패키지 이름, 고정 원본, 원본·현재·준비 파일 해시, 보존·제거 후보, 적용 패치를 제공한다. 다음 Task는 검증이 끝난 후보 목록과 복구 manifest만 사용한다.

- [x] `git status --short`, `git rev-parse HEAD`, `git worktree list`로 기준선·격리·사용자 변경을 확인하고 기존 전체 회귀를 실행한다.
- [x] 승인된 준비 A 32개·B 25개의 원본 커밋과 전체 파일 해시·리소스·패치 검토 상태를 확인한다. 두 묶음의 이름이 겹치거나 미해결 차단 사유가 있으면 적용하지 않는다.
- [x] 현재 `~/.agents/skills/` 103개와 보호 대상 목록·파일 해시를 기록한다. 패키지 경계·junction·symlink·경로 이탈과 미확인 로컬 파일을 검사한다.
- [x] 변경·이름 전환·퇴역 대상의 전체 복구 자료를 검색 경로 밖에 만들고 원래 파일 목록·해시와 일치하는지 검증한다.
- [x] 검증용 복사본에서 기준 해시 불일치와 경계 밖 경로를 입력해 적용 전 차단되는지 확인한다. 기존 현재 상태와 준비 목표가 다른 항목은 차이를 확인하며 아직 목표와 같다고 통과 처리하지 않는다.

이 작업은 파일 배치·문서 변경이므로 제품 기능을 위한 새 RED 테스트를 만들지 않는다. 배치용 비공개 도구에 새 분기·경로 검사·복구 로직을 작성하면 정상·해시 충돌·경계 이탈·복구 반례를 포함한 작은 자체 검증을 먼저 실행한다.

### Task 2. 검토된 패키지만 적용하고 전환·퇴역을 검증한다.

**Files:** `~/.agents/skills/<검증된 후보 이름>/`와 `~/.agents/skills/firecrawl/`, 이전 `~/.agents/skills/firecrawl-cli/`·`~/.agents/skills/skill-gen/`만 변경 대상으로 삼는다. 비공개 적용 manifest에 실제 변경·동일·보류·복구 결과를 기록한다.

**Interfaces:** Task 1의 검증된 준비 파일·현재 기준 해시·복구 manifest를 입력으로 받고 패키지별 결과 해시와 실제 변경 파일 목록을 산출한다. 공개 문서는 Task 4에서 허용 필드만 사용한다.

- [x] 적용 직전 현재 해시를 다시 대조하고 동일 패키지를 구분한다. 드리프트·개인 파일 충돌·준비 manifest 변경 시 중단하고 재검토한다.
- [x] 변경이 필요한 후보만 필요한 보조 리소스와 함께 반영하고 각 패키지의 전체 결과 파일 해시를 준비 manifest와 대조한다. 기록한 호환성·보안 패치 외 차이는 허용하지 않는다.
- [x] `firecrawl`을 배치·검증한 뒤 이전 `firecrawl-cli`를 활성 경로에서 제거한다. `skill-gen`은 전체 백업·로컬 추가 자료 보존 확인 후 개별 파일로 퇴역시킨다.
- [x] 준비된 검증용 복사본에서 중간 실패와 재시작을 확인한다. 부분 적용은 해당 변경 패키지만 복구하고 이미 성공한 패키지는 결과 해시로 식별해야 한다.
- [x] 전역 102개와 `firecrawl` 단일 활성, `firecrawl-cli`·`skill-gen` 부재를 검사한다. 유지 45개·별도 6개·플러그인 24개와 Claude·설정·CLI 보호 범위의 해시가 유지됐는지 확인한다.

예상 GREEN은 준비 manifest 일치·이름 전환·퇴역 결과와 비대상 보존이 모두 통과한 상태다. 성공 패키지 수는 실제 내용 변경 수와 별도로 기록한다.

**Interfaces:** Task 2의 실제 설치 manifest와 계정·작업 경로가 확인된 발견 목록을 대조한다. 완료·미검증 결과를 구분해 Task 4에 전달한다.

## Git 반영과 정리.

검증과 전체 리뷰 후 승인된 관련 문서를 한글 커밋으로 묶는다. 로컬 설치본·타사 원문·원시 조사·복구 자료는 스테이징하지 않는다. 승인된 병합·일반 push 후 로컬·원격 SHA와 작업 상태를 확인하며, 성공 기록은 실제 Git 결과 이후 남긴다. 에이전트 소유 임시 작업 공간은 참조·미커밋 변경·복구 필요 여부를 확인하고 정리하며 복구 자료는 보존한다.
