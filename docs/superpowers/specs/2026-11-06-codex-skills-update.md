# Codex 전용 스킬 업데이트 설계.

## 승인과 기준선.

저장소 기준선은 `13e3566ada503dfb1badec39c5bb79c554dff36e`다. 사용자는 제시된 설계에 대해 “설계안대로 진행”하도록 승인한 뒤 적용 대상을 Codex로 한정했다. 기존 Codex 전역 스킬 103개를 조사해 필요한 패키지만 갱신하고, 호환성 때문에 보류하거나 이미 최신인 항목은 유지한다. Claude 설치본·설정·캐시, 두 클라이언트의 설정·인증·CLI 실행 파일은 변경하지 않는다.

## 선택한 접근.

기존 `~/.agents/skills/<name>` 패키지 구조를 유지하며 공개 제작자 원본의 고정 커밋에서 기존 기능과 필요한 보조 리소스를 준비한다. 마켓플레이스 전체를 새로 설치하는 방법은 승인 범위 밖의 스킬·MCP·설정을 추가할 수 있고, 최신 HEAD 일괄 복사는 안정 배포와 호스트 호환성을 구분하지 못하므로 선택하지 않았다. 별도 준비 영역에서 전체 패키지·현재 파일·최소 호환성 패치를 대조한 뒤 적용한다.

준비 묶음 A는 Hugging Face 18개·Figma 8개·Chrome DevTools 6개로 32개다. 준비 묶음 B는 Anthropic 계열 14개·Unity 1개·Firecrawl 10개로 25개다. 합계 57개는 검토·적용 후보 수이며 실제 내용이 달라지는 패키지 수를 뜻하지 않는다. 현재 파일과 동일한 패키지는 불필요하게 교체하지 않는다.

## 이름·퇴역·유지 경계.

Firecrawl은 기존 `firecrawl-cli`를 현재 원본의 `firecrawl`로 전환하고 나머지 9개 기본 기능을 유지한다. 구식 command 요약인 `skill-gen`은 Codex 활성 전역 설치에서 퇴역시킨다. 새 이름 배치와 검증에 성공한 후 이전 이름을 제거하며, 로컬 추가 자료는 검색 경로 밖의 복구 자료로 보존한다. 동명 `skill-creator`, Claude command와 다른 사용자 파일은 이 퇴역에 포함하지 않는다.

Qodo 2개는 새 원본이 요구하는 런타임·API 호환성이 확보되지 않아 현재 설치를 유지한다. 런타임 설치·인증·MCP 추가로 이 보류를 우회하지 않는다. 자체 제작 25개, Superpowers `7.0.2` 15개와 공개 실행 원본 미확인 로컬 변환 3개도 유지한다. 따라서 전역 103개는 후보 57개·퇴역 1개·유지 45개로 나뉘며 이름 전환 자체는 개수를 늘리지 않는다. 정상 적용 후 전역 예상 수는 102개다.

별도 설치 migrate-to-codex 1개·내장 5개와 현재 앱 세션 노출 플러그인 24개는 별도 범위다. Superpowers·Ponytail `5.3.3` 등 최신 확인 항목을 유지한다. 네이티브 관리 항목의 변경은 공식 관리 경로만 허용하며 원하는 버전을 공식 경로에서 선택할 수 없으면 이번 작업에서는 보류한다. 관리 캐시를 직접 덮어쓰지 않는다. 이 범위를 유지하면 출처 관리 대상 합계는 `102 + 6 + 24 = 132`개다.

실제 사용자 계정의 새 CLI app-server에서는 적용 전 전역 103개·별도 1개·내장 5개·플러그인 14개로 123개를 발견했다. 해당 목록은 모두 활성이고 오류가 없었다. 앱 세션의 24개 중 pages 4개·plugin-management 1개·sites 2개·work-pets 3개는 설치·활성 등록돼 있어도 새 CLI에 노출되지 않았다. 따라서 이번 적용 후 새 CLI 발견 기대 수는 122개이며 출처 관리 132개와 구분한다. 설치 파일·관리 캐시·설치 및 활성 등록·현재 앱 세션·새 CLI 발견을 서로 대신하지 않는다. 네이티브 browser/chrome은 공개 원본이 있어도 캐시의 skills가 비어 있는 상태를 임의로 복구하지 않는다.

## 적용·실패·복구 흐름.

현재 파일 목록과 해시, 보존할 로컬 추가·수정 파일, 비대상 스킬과 설정의 해시를 먼저 기록하고 검색 경로 밖에 복구 자료를 만든다. 준비 파일의 모든 경로가 해당 패키지 안에 있는지 확인하며 junction·symlink와 상대경로가 승인 경계를 벗어나면 적용하지 않는다. 원본이 소유한 파일과 개인 추가 파일을 구분해 패키지 전체를 대조한다.

공개 원본과 다른 호스트 호환성·보안 패치는 준비 manifest에 파일·차이·이유를 남기며 원본 일치로 표기하지 않는다. 런타임에 필요한 누락 리소스·호환되지 않는 도구 계약·개인 파일 충돌은 적용을 막는다. 실행과 관계없는 원본 문서 링크 경고는 영향과 미검증 범위를 기록한다. 개인 참조와 기존 업로드·권한 검증을 약화하지 않는다.

적용 직전 현재 해시가 조사 기준선과 달라졌으면 덮어쓰지 않고 원인을 확인한다. 중간 실패 시 해당 작업에서 바뀐 패키지만 검증된 복구 자료로 되돌린다. 재시작할 때 이미 적용된 패키지는 결과 해시로 구분하고 남은 후보를 다시 검증한다. 복구 자료·원시 조사 JSON·타사 실행 원문은 공개 저장소에 넣지 않는다.

## 검증과 완료 조건.

1. 준비 manifest의 모든 파일과 보조 리소스가 실제 배치 결과와 일치하고, 기록한 패치 외 차이와 허가하지 않은 새 스킬이 없어야 한다.
2. `firecrawl`은 하나만 발견되며 Codex 활성 경로의 `firecrawl-cli`·`skill-gen`은 없어야 한다. 유지 45개·별도 6개·플러그인 24개와 Claude·설정·CLI의 보호 범위가 보존돼야 한다.
3. 실제 사용자 계정의 새 Codex CLI app-server에서 전역 102개·전체 122개와 대상 경로·활성·오류·중복을 확인하고 새 읽기 전용 세션에서 대표 스킬 읽기를 확인한다. 출처 관리 132개와 loader별 발견 차이를 기록하며 다른 샌드박스 프로필의 목록·열린 세션 캐시를 실제 사용자 설치 검증으로 사용하지 않는다.
4. 스크립트가 있는 패키지는 필요한 최소 정적 검사·로컬 자체 검증을 실행하고 저장소 전체 회귀, 문서 링크·인코딩·공개정보 검사와 독립 전체 변경 리뷰를 통과해야 한다. 외부 서비스 실행·인증이 필요한 항목은 실제 검증과 미검증을 구분한다.
5. 이전 [출처 기록](../../../references/skill-provenance-2026-11-06.md)은 조사 당시의 이력으로 보존하고 별도 업데이트 기록에 적용·동일·보류·퇴역, 고정 원본·번들 버전·본문 지문·패치·미검증을 구분한다. 검증 전에는 구현 완료로 표시하지 않는다.

## 문서와 Git 반영.

후속 실행에서 `references/codex-skill-update-2026-11-06.md`, `docs/reviews/2026-11-06-codex-skills-update.md`, 현재 상태·진행 체크리스트·변경 이력과 필요한 설치 안내를 실제 결과에 맞춘다. 기존 카탈로그에 Codex 이름 전환·퇴역을 안내할 때는 클라이언트 범위를 명시하고 Claude 설명·과거 조사 개수를 Codex 설치 수로 덮어쓰지 않는다. 과거 출처·설치 기록을 보존한다. 검증과 리뷰 후 승인된 방식으로 관련 문서를 한글 커밋으로 묶으며 병합·푸시 성공은 실제 Git 결과로 확인한다. 이 설계 문서 작성은 설치 적용·커밋·푸시 완료를 뜻하지 않는다.

## 실제 적용과 검증 경계.

후보 57개 중 48개 패키지를 갱신하고 9개는 동일 유지했으며 전역 102개·출처 관리 132개를 확인했다. 실제 사용자 계정 새 CLI는 두 작업 경로 각각 122개·전체 활성·오류 0이었다. 보호 범위 해시와 배치 결과·AST·배치 도구 자체 검증을 확인했다. 새 모델 호출에 의한 대표 스킬 읽기와 외부 로그인·실제 CLI/GPU/Bash 실행은 미검증으로 남기며 파일 전체 읽기·정적 검사를 해당 실행 성공으로 해석하지 않는다. 전체 회귀·최종 문서 리뷰·Git 반영은 [검증 기록](../../reviews/2026-11-06-codex-skills-update.md)과 실제 결과로 확인한다.
