# 분야별 스킬 선택 안내 설계.

## 승인과 목표.

사용자는 분야별 선택 안내 설계를 승인하고 README 정리·검증·커밋·푸시를 요청했다. 후속 논의에서 저장소를 먼저 수정·검증한 뒤 로컬 전역 문서를 동일한 내용으로 독립 복제하는 순서를 확정했다. 기준선은 `26d70e7`이다. 바탕화면 저장소를 삭제해도 전역 진입점·문서·설치 스킬 참조가 유지돼야 한다.

## 선택한 구조.

CATALOG 내부 확장은 전체 목록과 선택 조건을 섞고 기존 144개 상세 링크 계약에 영향을 준다. 분야별 폴더 재배치는 출처·설치·상대경로를 복잡하게 한다. `Skill/BY-TASK.md` 한 파일에서 12개 분야의 대표 도구·선택 조건·호출 경계를 안내하고 기존 상세 설명으로 연결한다. 상세 설명·설치 명령·버전은 기존 문서에서 관리한다.

분야는 엑셀, PPT, 문서, 시각 디자인, 웹 UI, 리서치, 개발, 디버깅·리뷰, AI 학습, 에이전트·MCP·Unity, 환경·세션·반복, 배포다. 고정 `task-*` 앵커와 바로가기 표를 두고, 여러 분야의 도구는 같은 상세 설명을 재사용한다. 설치·노출·인증·명시 호출·과거 비활성 기록을 구분하며 성능 순위나 현재 사용 가능성을 단정하지 않는다. 전체 항목은 기존 CATALOG에서 찾게 한다.

## 문서와 실행 경계.

한·영 README, Skill 인덱스와 CATALOG에서 새 안내를 연결한다. 기존 144항목·26그룹·자체 제작 패키지·고정 명세·스킬 실행본·MCP·권한·인증 설정은 보존한다. 현재 상태·체크리스트·변경 이력·리뷰는 이번 작업의 실제 증거로 갱신한다.

전역 복제본과 전역 AGENTS는 외부의 비공개 백업에 상대경로·SHA256을 보존한 뒤 갱신한다. 복제본은 저장소 추적 파일과 이번 신규 파일의 집합을 그대로 물리 복사하고 이전 extra 파일은 검증된 백업에 보존한 뒤 활성 복제본에서 개별 제거한다. 전역 AGENTS는 저장소의 전역 템플릿에 사용자 고유 마무리 절을 보존한다. 개인 경로·백업·원문 로그는 공개 저장소에 넣지 않는다.

## 실패와 재시작.

백업 불일치·동기화 중 원본 변경·예상하지 못한 extra·reparse point를 발견하면 복사를 중단하고 원본을 보존한다. 배포 대상 목록과 SHA를 고정하고 복제 후 파일 집합·해시·링크를 대조한다. 바탕화면 위치를 사용하지 않고 전역 복제본만으로 검사한다. 실제 스킬 설치 폴더는 재배치하지 않는다.

## 검증과 완료 기준.

분야별 목적지·12개 앵커·대표 시나리오·진입 링크·공유 도구·명시 호출과 비활성 경계를 검사한다. 기존 전체 회귀, 전체 링크·앵커, diff 검사와 독립 리뷰를 통과한다. 전역 백업·동일성·자기완결 참조와 기존 설치 패키지 보존을 확인하고 한글 커밋·main 통합·일반 push·원격 SHA 및 CI 결과를 확인한다. 새 세션의 자동 선택 개선이나 Office 실행 품질은 이 문서 변경의 완료 증거로 주장하지 않는다.
