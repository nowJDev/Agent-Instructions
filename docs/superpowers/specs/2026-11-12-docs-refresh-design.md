# 문서 전체 정리 설계.

## 요청과 기준.

사용자는 신규 스킬 설치 뒤 README부터 모든 문서를 갱신하고 깔끔하게 정리하도록 요청했다. 기준선은 `3c4dd83`이다. 추적 Markdown 152개를 루트·참조, 스킬·MCP, 작업 기록·자체 제작 패키지로 나눠 전체 읽기와 출처·구조를 점검한다. 고정 설치 명세와 실제 실행 증거를 기준으로 하며 새 설치나 스킬 동작 변경을 포함하지 않는다.

## 구조와 선택.

모든 파일을 현재 수치로 바꾸면 과거 증거가 손상된다. 새 설명 문서를 계속 늘리면 길찾기가 더 어려워진다. 기존 README·GUIDE·카탈로그 역할을 유지하면서 현재 안내를 갱신하고 종료 작업은 기존 history 방식으로 보관한다.

- 한·영 README에는 Anthropic·Office/design·Unity 안내로 가는 같은 진입점을 둔다. 세부 수치는 카탈로그·고정 명세에서 관리한다.
- Skill 목차는 설명 수와 실제 설치·현재 노출을 구분하고 명시 호출·역할 중첩·의존성 내부 스킬 발견을 안내한다.
- MCP·이식 안내는 작성 당시 Claude 스냅샷과 실제 클라이언트 지원·연결·인증을 구분한다. 과거 상태만으로 연결·이식 불가를 단정하지 않는다.
- 종료된 설계 5개·계획 6개·리뷰 6개를 6개 작업별 history 문서로 묶는다. 원문 사실·코드·실패·미검증과 원래 경로·기준 커밋 링크를 보존하고 제목·앵커·상대 링크만 새 위치에 맞춘다.
- current-state·체크리스트는 이번 작업과 최신 구성·실제 한계만 요약하고 지난 작업의 진행 서술은 보관 목차로 연결한다.
- Owned-Skills의 실행 지침·템플릿·합성 fixtures와 고정 JSON·원본 출처 기록은 보존한다. 역사 참조는 날짜·최신 목차 안내를 보강할 수 있다.

## 검증과 완료.

기준선 전체 문서의 파일별 SHA256·읽기 coverage와 보관 전후의 비구조 본문 동일성을 기록한다. 보관 경로·앵커·목차·테스트 기대값을 함께 갱신한다. 내부 링크·한영 README·전체 회귀·공개 정보·독립 전체 리뷰를 통과하고 한글 커밋·main 통합·일반 push·원격 SHA·CI를 확인한다. 타사 원본·개인 자료·실행 로그를 공개하지 않으며 전역 환경·설치 스킬·권한은 바꾸지 않는다.
