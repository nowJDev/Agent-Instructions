### 스타 저장소 선별 반영 설계.

사용자는 후보 전체의 균형 있는 상세 설계를 검토한 뒤 설계대로 실행하도록 승인했다. 포니테일 중심 통합과 추천 후보의 일괄 설치는 범위에서 제외했다.

<a id="spec--목표와-기준선"></a>
#### 목표와 기준선.

- 기준선은 `a463ec8c82a3f013ceba7fdd281179b17369448c`다.
- 기존 요구사항·승인·TDD·검증·리뷰·인수인계 절차를 유지하고 부족한 판단 기준을 구체화한다.
- 요구사항·구현·문서·컨텍스트·도구 선택의 다섯 영역을 함께 보완한다.
- 검토 대상 26개 각각의 채택·중복·사용조건·출처·검증 범위를 한 참고 문서에 기록한다.

<a id="spec--책임과-흐름"></a>
#### 책임과 흐름.

`AGENTS.md`는 결론 우선·사실 보존의 핵심 출력 규칙을 안내한다. 자체 제작 전달 스킬의 `change-workflow.md`는 기존 해결책·변경 영향·구체적 요구사항·완료 기준을 관리한다. `document-contracts.md`는 상세 규칙의 단일 출처와 읽을 조건을 관리한다. `rules/02`는 도구 사용 불가 시 대체와 도입 경계, `rules/04`는 큰 출력과 원본 증거를 관리한다.

정식 규칙은 위 위치에 두고 `references/starred-repo-adoption.md`에는 채택 근거와 선택 도구 안내를 둔다. README와 사람용 설명서에서 필요할 때 찾을 수 있게 연결한다.

<a id="spec--채택-범위"></a>
#### 채택 범위.

- mattpocock/skills는 실제 시나리오·용어·완료 기준·문서 포인터를 참고한다.
- ponytail과 ECC는 기존 해결책·재사용·호출자와 테스트·설정 영향 확인을 참고한다.
- humanizer와 i-have-adhd는 결론·행동 우선과 사실·불확실성 보존을 참고한다.
- context-mode와 ECC는 큰 출력 취급을 참고하되 기존 상태 보존 항목을 재사용한다.
- archify·context-mode·Agent-Reach·open-code-review·openai/plugins는 선택 조건만 안내한다.
- context-forge·openrig는 운영 참고, hyperframes·anotifier·claude-session-manager는 작업별 보류다.
- 분야별·일반 도구 10개는 공통 지침 반영 대상에서 제외하고 snap-path는 사용자 지정으로 제외한다.

<a id="spec--비목표와-안전-경계"></a>
#### 비목표와 안전 경계.

추가 설치, hooks·권한·전역 설정 변경, 설치된 스킬 갱신, 원격 게시·푸시는 하지 않는다. 타사 실행 원본을 복제하거나 새 스킬·MCP를 카탈로그에 추가하지 않는다. 후보를 설치·활성 상태로 단정하지 않으며 기존 카탈로그 수를 늘리지 않는다.

모호한 요청은 결과를 바꾸는 부분만 확인한다. 새 용어집·ADR·메모리 체계를 강제하지 않는다. 포니테일이 있어도 승인·필수 검증·기능/버그 TDD·무관한 기존 코드 삭제 경계를 유지한다. 문체 편집은 코드·인용·오류 로그를 임의로 고치지 않는다. 큰 출력 요약은 수정 파일의 전체 읽기와 실패 증거 확인을 면제하지 않는다.

개인 계정·로컬 절대경로·인증 정보는 공개 문서에 옮기지 않는다. 타사 자료는 원본 링크로 안내하며 실제 도입 시 해당 라이선스와 환경 지원을 확인한다.

<a id="spec--실패와-재시작"></a>
#### 실패와 재시작.

문서 검사나 리뷰에서 누락·모순·깨진 링크를 발견하면 관련 문구를 수정하고 검증을 다시 실행한다. Git 작업은 기준선과 사용자 변경을 확인한 격리 브랜치에서 수행한다. 도구 실행 실패는 문서 검증 결과와 구분해 보고하며 재개 시 계획의 미완료 항목과 증거를 확인한다.

<a id="spec--검증과-완료-조건"></a>
#### 검증과 완료 조건.

- 후보 표의 번호 1~26과 저장소가 원래 검토 목록과 일치한다.
- 변경 문서의 UTF-8/BOM·줄바꿈·코드 펜스·로컬 링크와 앵커를 검사한다.
- 카탈로그·설치 원본·전역 설정이 변경되지 않았는지 diff로 확인한다.
- 읽기 전용 요청·재사용 가능한 변경·모호한 요청·문체 편집·큰 출력·미설치 도구·포니테일 사용 여부의 7개 사례로 지침을 검토한다.
- HTML 안내는 실제 브라우저에서 새 링크와 레이아웃을 확인한다.
- 전체 diff 리뷰와 `git diff --check` 후 한 논리 변경으로 한글 커밋한다.

시나리오에 대한 지침 검토, 브라우저 확인, 새 세션에서의 실제 에이전트·hooks 실행은 별도 증거로 기록한다. 문서 검사만으로 새 세션의 동작이나 외부 도구 호환성을 검증했다고 주장하지 않는다.

#### 종료 작업.

<a id="plan--검증-명령"></a>
#### 검증 명령.

작업 루트에서 `git diff --check`, `git diff --name-only`, `git diff --stat`를 실행한다. 임시 Python 검사는 저장소를 인자로 받아 검사하며 성공 시 각 항목의 PASS와 개수를 출력한다. 커밋 후 `git show --stat`와 `git status --short --branch`로 논리 단위와 작업 트리를 확인한다.

저장소 전체를 고정 경로로 검사하는 workflow 스크립트는 기존 `docs/current-state.md`·`docs/design-progress-checklist.md`가 없는 구조를 요구하므로 이번 작업의 완료 근거로 쓰지 않는다. 기존 문서 구조를 유지하며 이번 설계·계획·리뷰와 실제 검사 결과를 대조한다.

### 스타 저장소 선별 반영 리뷰.

기준선은 `a463ec8c82a3f013ceba7fdd281179b17369448c`다. [승인 설계](#spec)와 [구현 계획](#plan)에 따라 기존 문서 9개와 신규 설계·계획·[후보 판단](../../references/starred-repo-adoption.md)을 검토했다. 독립 스펙 리뷰 후 별도의 품질 리뷰가 모두 PASS이며 수정이 필요한 고확신 발견 사항은 없다.

<a id="review--반영-내용과-경계"></a>
#### 반영 내용과 경계.

- 요구사항·구현·문서·컨텍스트·도구 선택의 다섯 영역을 기존 정식 위치에서 구체화했다. 포니테일 전용 절차나 카탈로그를 추가하지 않았다.
- 후보 26개 각각의 판단·기존 중복·사용조건·출처·확인 범위를 기록하고 snap-path는 사용자 지정 제외로 남겼다.
- 승인·기능/버그 TDD·필수 검증·전체 파일 읽기·기존 무관한 코드 삭제 경계를 유지했다. 사실과 불확실성을 문체 편집에서 보존하며 큰 성공 출력과 실패 증거를 구분한다.
- diff에는 스킬·MCP 카탈로그, 설치 원본·전역 설정·hooks·권한 변경이 없다. 타사 스킬 원본을 복제하지 않았으며 기존 개수를 유지했다.

<a id="review--자동-문서-검사"></a>
#### 자동 문서 검사.

임시 Python 표준 라이브러리 검사로 UTF-8/BOM 없음·LF·코드 펜스·로컬 링크와 앵커·후보 26개 번호/저장소·변경 범위·출력 규칙 두 템플릿의 일치·개인 정보와 시크릿 패턴을 확인했다. 검사기 자체의 앵커·HTML 링크·HTTPS와 드라이브 경로 구분도 assert로 확인했다.

첫 검사에서 전역 지침 템플릿의 배포 경로를 저장소 상대경로로 취급해 실패했다. 검사에 템플릿 경로 해석을 추가했다. 이후 HTTPS 링크를 드라이브 경로로 오인한 정규식을 수정하고 재실행했다. 문서의 실제 누락이나 시크릿 발견으로 보고하지 않았다.

리뷰 기록과 최종 계획을 포함한 문서 13개, 로컬 링크·앵커 95개, 후보 26/26 검사가 통과했다. `git diff --check`는 루트와 독립 리뷰어가 각각 실행해 통과했다.

<a id="review--브라우저-확인"></a>
#### 브라우저 확인.

Chrome에서 임시 로컬 서버의 `index.html#catalog`를 열고 스크린샷으로 새 안내 문구·읽을 조건·링크·기존 노출 수 99의 표시를 확인했다. 새 링크의 href는 `references/starred-repo-adoption.md`와 일치한다. 콘솔 경고·오류는 0개였다. 서버에서 기존 미제공 `favicon.ico` 요청은 404였으며 HTML 본문은 200이었다. 검증 탭과 임시 서버를 종료했다.

<a id="review--검증-범위"></a>
#### 검증 범위.

외부 후보의 설치·업데이트·성능·다른 PC 호환성과 전역 스킬 동기화는 수행하지 않았다. 실제 새 세션의 자동 지침 로드·포니테일 on/off·hooks 실행은 미검증이다. 위 7개 PASS는 문서 규칙의 적용 가능성 검토다. 모든 외부 링크의 현재 상태를 이번 품질 리뷰에서 다시 조회한 것은 아니며 실제 도입 시 원본·라이선스·지원 조건을 다시 확인한다.

이번 완료 범위는 저장소 문서 반영과 위 문서·브라우저 검증이다. 커밋·로컬 반영 결과는 최종 Git 확인으로 보고하며 원격 푸시는 하지 않는다.
