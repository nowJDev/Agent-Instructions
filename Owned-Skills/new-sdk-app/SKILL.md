# Claude Agent SDK 앱 준비.

## 입력과 사전 확인.
- 언어, 대상 디렉터리, 에이전트 목적, 패키지 관리자를 대화·기존 파일에서 확인한다. 빠진 정보만 한 번에 하나씩 묻는다.
- 설치된 `claude-api`와 `design-driven-delivery`가 있으면 적용하고 이미 승인된 계획은 재사용한다. 없어도 공식 문서·프로젝트 상태 확인→범위·계획 확정→최소 생성→정상·실패 검증 순서로 진행한다.
- 대상이 기존 프로젝트면 manifest·lockfile·지침과 전체 변경 파일을 읽는다. 빈 폴더라고 가정해 초기화하거나 기존 파일을 덮어쓰지 않는다.

## 실행 절차.
1. 설치된 SDK와 런타임을 먼저 조사한다. 새 앱에 필요한 공식 Agent SDK 문서의 해당 언어 가이드와 npm·PyPI 메타데이터에서 호환 버전을 확인하고 선택 버전을 기록한다.
2. 현재 문서를 조회할 수 없으면 오래된 API를 최신이라고 만들어 쓰지 않는다. 설치 버전의 로컬 문서·타입으로 확인한 범위만 준비하고 최신성 미확인을 표시한다.
3. 사용자 요구를 충족하는 최소 진입점, manifest·lockfile, 실행·검사 명령을 정한다. 도구·MCP·하위 에이전트·hooks는 실제 요구가 있을 때만 추가한다.
4. 기존 패키지 관리자로 프로젝트 범위에 의존성을 설치한다. TypeScript는 해당 프로젝트의 타입 검사, Python은 대상 인터프리터의 문법·import 검사를 준비한다. 예제 API와 import는 선택한 SDK 버전의 공식 예제를 기준으로 한다.
5. 키는 환경변수나 지원 인증 경로로 주입한다. `.env.example`에는 자리표시자만 쓰고 실제 키는 읽어 출력하거나 커밋하지 않는다. 키 유무는 값 없이 확인한다.
6. 입력 처리와 실패를 설명하는 작은 예제를 작성한다. 신규 소스 첫 줄에 한국어 역할 주석을 넣고 기존 오류 처리·권한 경계를 따른다.
7. 실제 타입·문법·import 검사를 실행한다. 누락된 도구를 이유로 다른 검사를 통과했다고 보고하지 않는다.
8. 인증과 외부 호출이 요청 범위에 있으면 비용·권한 범위를 확인한 최소 요청으로 정상·실패를 검증한다. 키가 없으면 로컬 검사 결과와 원격 실행 미검증을 구분한다. 테스트를 위해 임의 키를 만들거나 계정 설정을 바꾸지 않는다.

## 결과와 오류.
- 설치 버전, 생성·변경 파일, 실행·검사 명령, 결과와 필요한 환경변수 이름을 제공한다.
- 기존 폴더 충돌은 내용을 보존하고 다른 위치 또는 필요한 개별 수정만 선택한다. 설치 실패는 오류 원인을 확인하고 무작정 전역 설치로 우회하지 않는다.
- 빌드 성공과 실제 모델 응답 성공은 다른 증거다. 인증·원격 실행이 남으면 해당 제한을 명시한다.
- 전용 검증 에이전트가 없어도 같은 점검을 현재 도구로 직접 수행한다.

## 참고.
