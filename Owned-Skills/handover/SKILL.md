# 세션 인수인계.

다음 세션이 사용자 지시·현재 상태·검증 근거를 읽고 바로 이어갈 수 있는 md 파일을 만든다.

## 입력과 환경 확인.

- 현재 대화에서 보이는 작업 목적·승인 범위·제약과 실제 프로젝트 루트를 확인한다.
- 사용자가 지정한 프로젝트명·출력 위치가 우선이다. 여러 프로젝트가 섞였거나 홈 폴더만 보이면 대상부터 확인한다.
- 클라이언트의 대화·task 조회 도구가 있으면 필요한 범위만 읽는다. 이전 대화 전체에 접근할 수 있다고 가정하지 않는다.
- 조회 도구가 없으면 현재 대화와 파일·Git 상태로 확인하고 접근하지 못한 과거 내용은 한계로 남긴다.
- task 조회는 새 task 생성·전송 권한이 아니다. 문서 작성 요청을 외부 전송으로 확대하지 않는다.

## 저장 위치와 이름.

- 미지정 출력 폴더는 프로젝트 루트 아래 `docs/handovers/`다. 기존 프로젝트 인수인계 폴더나 명시된 사용자 경로가 있으면 우선한다.
- 파일명은 `HANDOVER_{project-name}_{YYYYMMDD}_{topic-slug}.md`로 만든다.
- 프로젝트명은 사용자 명시 → Git 루트 폴더명 → 현재 프로젝트 폴더명 순으로 결정한다.
- 프로젝트명의 공백은 `-`로 바꾸고 파일명 금지 문자는 제거한다. 프로젝트를 특정할 수 없으면 추정하지 않는다.
- `topic-slug`는 실제 작업 주제를 영문 kebab-case 2~5단어로 적고 프로젝트명 반복을 피한다.
- 날짜는 현재 사용자 시간대를 쓴다. 기존 파일이 있으면 `_2`, `_3`을 붙여 덮어쓰지 않는다.

## 내용 작성.

1. 현재 목표·완료 범위·진행 중인 일·바로 다음 행동을 먼저 적는다.
2. 사용자 지시와 금지사항, 승인된 설계 결정·선택 이유를 보존한다.
3. 변경 파일과 변경 이유, 브랜치·worktree·미커밋 상태를 실제 조회 결과로 적는다.
4. 실패한 접근과 원인, 미해결 오류의 원문·발생 조건·관련 경로를 필요한 범위로 남긴다.
5. 검증 명령·실행 위치·결과·실행 시점과 미실행 항목을 구분한다. 계획한 테스트를 통과했다고 쓰지 않는다.
6. 완료/미완료 체크리스트, 참조 설계·계획·리뷰·백업 경로와 다음 세션의 시작 순서를 적는다.
7. 비밀값·인증 헤더·개인 설정은 복사하지 않는다. 필요한 변수명과 안전한 보관 위치 참조만 남긴다.
8. 내부 프로젝트 지식은 승인된 비공개 출력에만 두고 외부용 문서나 Git 추적 파일에 섞지 않는다.

## 저장 실패와 검증.

- 대화 원문·로그 전체 덤프 대신 재현·복구에 필요한 근거를 요약한다. 모르는 내용은 미확인으로 적는다.
- 출력 폴더의 실제 경로와 쓰기 권한을 확인하고 UTF-8로 새 파일을 만든다.
- 쓰기 실패 시 기존 문서를 덮어쓰거나 임의의 공유 폴더로 옮기지 않고 원인과 준비된 내용을 보고한다.
- 저장한 파일을 재읽어 사용자 지시·남은 일·검증 결과·상대/절대 참조가 빠지지 않았는지 대조한다.
- 파일 존재·인코딩·충돌 회피와 비밀정보 누락 처리를 확인하고 생성 경로를 제공한다.
- 완료 보고에는 파일 링크와 다음 시작 행동, 확인하지 못한 이전 대화·실행 검증을 짧게 적는다.
