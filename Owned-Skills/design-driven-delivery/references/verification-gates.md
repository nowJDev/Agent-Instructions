# 검증 게이트.

## 검증 순서.

```text
대상 테스트.
→ 관련 회귀.
→ 전체 테스트.
→ 정적 검사.
→ 빌드·패키징.
→ 실제 앱·기기·운영 환경.
→ 전체 코드 리뷰.
→ 문서·Git 정합성.
```

## 자동 검증.

- 변경 동작을 직접 검출하는 대상 테스트를 실행한다.
- 프로젝트의 전체 테스트 스위트를 실행한다.
- lint, format, type check, compile과 build를 프로젝트 규칙에 맞게 실행한다.
- 결과의 total, passed, failed, skipped와 종료 코드를 확인한다.
- 로그에서 assertion, unhandled exception, missing reference와 경고 승격을 확인한다.
- 테스트를 실행하지 못했으면 성공으로 보고하지 않는다.

## 정적 검사.

- `TODO|TBD|FIXME|HACK` 같은 임시 표현.
- 시크릿, 인증 정보와 개인 설정.
- 금지된 계층 의존성.
- 전역 탐색, 동명 리소스 의존과 불안정한 순서.
- 누락 파일, 깨진 참조와 중복 식별자.
- 런타임에 포함되면 안 되는 개발 도구와 모델.
- 보호 경로와 공급자 원본 변경.

프로젝트 지침에 맞는 정확한 경로로 검사한다.

## 수동 검증.

다음은 자동 테스트만으로 완료하지 않는다.

- 사용자 경험, 가독성, 접근성과 입력 감각.
- 실제 기기·브라우저·운영체제·네트워크.
- 배포 권한과 파일 시스템 경계.
- 장시간 실행과 성능.
- 외부 서비스의 실제 계약과 장애 대응.

날짜, 환경, 버전, 수행 경로, 합격·실패와 로그를 기록한다.

## 코드 리뷰.

- 승인 기준선부터 전체 diff를 검토한다.
- 정확성, 상태, 수명, 실패 격리와 테스트 신뢰성을 확인한다.
- 재사용·단순화·효율성과 보안을 확인한다.
- 차단·중요 발견을 해결하고 검증을 다시 실행한다.

## 문서 게이트.

- 설계와 구현이 일치한다.
- 계획 체크박스가 실제 실행과 일치한다.
- 체크리스트 상태가 자동·수동 증거와 일치한다.
- 리뷰 문서에 전체 대상이 기록된다.
- 남은 위험과 미검증 항목이 명시된다.

## Git 게이트.

- `git status`, 전체 diff와 staged diff를 확인한다.
- `git diff --check`를 통과한다.
- 사용자 변경, 시크릿, 테스트 산출물과 보호 파일이 제외된다.
- 논리 커밋 후 작업 트리와 커밋 내용을 다시 확인한다.
- 병합·푸시 후 로컬과 원격 해시를 확인한다.
