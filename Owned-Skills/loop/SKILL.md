# 세션 안의 유한 반복.

각 반복의 결과를 확인하고 성공·최대 횟수·기한·오류·취소에 따라 종료한다.

## 입력과 실행 환경.

- 실행할 프롬프트/명령, 조회 대상, 간격, 성공 조건, 최대 횟수 또는 종료 기한을 확인한다.
- 상태 조회 요청을 수정·재배포·메시지 전송으로 확대하지 않는다. 각 작업의 기존 승인 범위를 지킨다.
- 현재 클라이언트와 가용 세션 반복·시간 대기·작업 조회·취소 도구의 실제 지원을 확인한다.
- Claude의 `/loop`나 `$ARGUMENTS`가 Codex에도 있다고 가정하지 않는다. 도구가 없으면 현재 턴에서 유한 반복만 수행한다.
- 한 번만 실행하면 되는 요청은 즉시 수행하고 loop를 만들지 않는다.
- 간격 생략 시 합리적인 간격을 먼저 알린다. 횟수·기한·완료 조건이 불분명하면 시작 전에 필요한 한계를 확인한다.
- 세션 종료 뒤에도 계속할 요청은 영구 예약과 구별한다. [Claude 일정 실행 문서](https://code.claude.com/docs/en/scheduled-tasks)도 실제 클라이언트 지원 범위에 맞춰 확인한다.

## 반복 절차.

1. 시작 시 대상·간격·최대 횟수/기한·성공 조건·취소 방법을 짧게 명시한다.
2. 현재 상태를 한 번 조회하고 결과·시각·시도 번호를 기록한다. 즉시 성공이면 종료한다.
3. 실패/미완료를 구분하고 최대 횟수·기한·사용자 취소를 확인한다.
4. 다음 실행 시각까지 가용 대기 도구를 사용한다. 한 번의 차단 대기는 60초 이내로 나눠 사용자 중단을 받을 수 있게 한다.
5. 이전 호출이 끝난 뒤 다음 호출을 시작한다. 느린 호출을 겹치게 실행하거나 놓친 간격을 몰아서 실행하지 않는다.
6. 매 결과를 성공 조건과 대조한다. 예를 들어 최대 3회·성공 즉시 종료 요청은 어느 한 조건을 먼저 만나면 끝낸다.
7. 대기 중 새 사용자 입력이 오면 중단·간격 변경·대상 수정을 반영하고 원래 범위를 보존한다.
8. 긴 대기에는 새 사실·남은 한계·다음 확인을 간결하게 알린다. 같은 상태를 불필요하게 반복 출력하지 않는다.

## 오류와 취소.

- 인증·권한·대상 부재·데이터 오류는 중단하고 원인을 보고한다. 오류를 미완료 상태로 감춰 무한 재시도하지 않는다.
- 일시 오류 재시도는 전체 최대 횟수/기한 안에서만 허용하고 별도 무한 루프를 만들지 않는다.
- 사용자가 취소하면 추가 호출을 멈추고 실행 중인 자체 작업만 지원되는 취소 도구로 종료한다.
- 취소 지원이 없어 현재 호출을 멈출 수 없으면 그 상태를 알리고 다음 반복을 시작하지 않는다.
- 세션/턴이 종료되면 실행이 지속된다고 보장하지 않는다. 도구가 없는데 백그라운드 실행 완료라고 말하지 않는다.

## 영구 예약과 결과 증거.

- 임의 cron·작업 스케줄러·클라우드 task·Stop hook을 만들어 세션 반복을 영구화하지 않는다.
- 영구 예약은 사용자의 해당 요청과 지원 도구·일정·시간대·종료·전송 범위가 정해진 경우에만 별도 처리한다.
- 예약 조회 권한을 새 예약 생성이나 타인에게 메시지 전송 권한으로 확대하지 않는다.
- 최종 결과에 각 시도의 시각·관측 결과·실제 횟수·종료 이유·오류·취소 상태를 남긴다.
- 성공은 관측 증거로 확인한다. 최대 횟수 소진은 성공과 구분하고 마지막 상태와 필요한 다음 행동을 알린다.
- 만들거나 종료한 자체 세션 작업이 있다면 ID와 정리 결과를 적고 실제로 하지 않은 미래 실행은 약속하지 않는다.
