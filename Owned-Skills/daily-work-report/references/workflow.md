# 파일 선택과 대화 상태.

## STEP 1. 파일 지정 및 분석.

1. 현재 메시지의 폴더 위치와 정확한 파일명 목록을 확인한다. 완전한 파일 경로 목록도 받는다. 상대경로는 사용자가 지정한 기준 폴더로 해석하며 불분명하면 그 기준만 묻는다.
2. `.md`·`.txt`를 우선 지원한다. 공백·한글·Windows 역슬래시를 포함한 경로는 리터럴 경로와 안전한 인용으로 처리한다. Python의 `Path.read_text(encoding='utf-8-sig', errors='strict')`처럼 손상 바이트를 거부하는 판독으로 전체를 읽는다. PowerShell `Get-Content -LiteralPath <경로> -Raw -Encoding UTF8`은 손상 바이트를 치환할 수 있으므로 단독 성공을 인코딩 검증으로 삼지 않는다.
3. 각 파일 전체를 읽는다. 매우 긴 문서는 구간별로 끝까지 읽고 섹션·줄 범위의 누락을 확인한다. 제목·앞부분만 읽고 분석 완료라고 하지 않는다.
4. 선택 파일명, 읽은 시점·가능한 변경 표시, 핵심 사실, 원본 구간과 상태를 현재 대화 문맥에 유지한다. 사용자 문서를 외부 서비스·장기 캐시에 저장하지 않는다.
5. [원본 분석](source-analysis.md)에 따라 중복과 시점 충돌을 정리한다.
6. 파일만 지정됐으면 간단한 확인과 핵심 분석 항목 몇 개만 답한다. 마지막 문장은 `업무명과 보고서 작성 지시를 입력해주세요.`다. 아직 보고서 초안을 출력하지 않는다.

선택 파일의 정확한 이름은 확인 응답에 표시할 수 있다. 원본에 있는 내부 절대 경로나 인증정보는 옮기지 않는다.

## 읽기 오류.

- 지정 파일이 없으면 누락된 정확한 파일명을 알린다. 이름이 비슷한 파일을 대체하거나 폴더 전체를 검색하지 않는다.
- 일부만 읽히면 성공·실패 파일을 구분한다. 나머지만 사용할지 물어보거나 읽힌 범위만 명시적으로 분석한다. 부분 자료를 전체 자료라고 표현하지 않는다.
- 전혀 읽히지 않으면 작성하지 않고 접근 가능한 정확한 경로를 다시 요청한다. Windows 드라이브가 현재 실행 환경에 없으면 접근 제한을 그대로 알린다.
- UTF-8 BOM은 허용한다. 잘못된 UTF-8을 무시·치환하거나 CP949 등으로 추측해서 읽지 않는다. 문제를 알리고 UTF-8 파일이나 명시적 인코딩 지시를 요청한다.

## STEP 2. 업무명과 작성 지시.

같은 대화에서 STEP 1이 끝났다면 짧은 업무명도 보고서 작성 요청으로 해석한다. 현재 지시와 직전 사용자가 제공한 보고서 템플릿을 우선한다.

- 업무명과 관련된 실제 수행 사실을 먼저 고른다. 관련 근거가 부족하면 부족함을 알리고 관련 있는 확정 사실만 쓴다.
- 날짜·번호·상태·진행률·완료예정일은 사용자 원문 그대로 유지한다. 없는 번호·진행률·완료일은 채우지 않는다. 날짜 미지정 시 Asia/Seoul 현재 날짜를 확인해 사용할 수 있다.
- 메타데이터가 없는 업무명만 받으면 제목·내용 중심으로 출력한다. 기본 10~12줄의 가짜 번호를 만들지 않는다. 반드시 필요한 정보만 한 가지 질문한다.
- 파일과 작성 지시가 처음부터 한 메시지에 함께 있으면 STEP 1 분석 뒤 즉시 STEP 2를 수행한다. 이미 제공한 업무명을 다시 묻지 않는다.
- 원본이 STEP 1 이후 바뀌었다는 증거가 있으면 선택한 해당 파일을 다시 전체 읽고 분석을 갱신한다. 근거 시점이 불명확하면 그 제한을 명시한다.

## 후속 상태.

| 입력 | 처리 |
|---|---|
| 좀 더 짧게·기술적으로·6개 항목으로. | 같은 선택 파일에서 요청한 길이·문체만 변경한다. |
| 업무명만 교체. | 새 업무명으로 바꾸고 실제 관련성을 다시 확인한다. 근거 없는 프로젝트 실적을 만들지 않는다. |
| 근거를 보여줘. | 보고 항목별 파일명·원본 구간·상태를 별도로 제시한다. 비밀 값은 가린다. |
| 다른 파일로 다시 할게. | 이전 선택을 폐기하고 새 정확한 목록을 받는다. 새 파일을 읽기 전 작성하지 않는다. |
| 새 정확한 파일 목록. | 새 STEP 1로 전환한다. 이전 자료와 자동 혼합하지 않는다. |
| 새 대화에서 호출. | 이전 대화의 선택을 상속하지 않는다. 파일 위치·파일명을 다시 지정받는다. |

압축·문맥 유실로 선택 파일이나 근거를 확인할 수 없다면 기억한다고 주장하지 않는다. 확인 가능한 정확한 목록을 다시 받거나 남은 목록의 파일을 다시 읽는다.
