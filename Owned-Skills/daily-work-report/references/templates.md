# 양식 해석과 예시.

아래 모든 내용과 수치는 구조를 설명하는 가상 예시다. 사용자가 지정한 자료를 읽기 전에는 수행 사실로 사용하지 않는다. 대괄호 자리표시는 실제로 확인한 값으로만 바꾼다.

## 기본 양식.

[기본 텍스트 양식](../assets/default-report-template.txt)을 참고한다. 업무 헤더는 사용자가 제공한 한 줄 전체를 그대로 쓴다. 10~12줄에 맞춰 근거가 있는 세부 6~8개를 선택한다.

```text
([사용자 날짜]) 일일 업무
1. 주요 업무내용
  [사용자 업무 번호·업무명·상태·진행률·완료예정일 전체]
    - [관련된 하루 작업 핵심 요약]
      = [실제 수행 내용과 결과 1]
      = [실제 수행 내용과 결과 2]
      = [실제 수행 내용과 결과 3]
      = [실제 수행 내용과 결과 4]
      = [실제 수행 내용과 결과 5]
      = [실제 수행 내용과 결과 6]
```

## 사용자 지정 10줄.

```text
[금일 주요 수행 업무]
- [핵심 요약]
- [상세 수행 1]
- [상세 수행 2]
- [상세 수행 3]
- [상세 수행 4]
- [상세 수행 5]
[검증 및 산출 결과]
- [확정 검증 1]
- [확정 검증 2]
```

이 양식은 custom으로 검사하고 `--max-lines 10`을 지정할 수 있다. 기본의 날짜·번호·`=`를 강제하지 않는다.

## 파일 위치와 첫 메시지.

아래 `<정확한 폴더 경로>`는 실제 사용자가 지정한 경로로 바꾼다. 예제 파일을 실제 존재한다고 가정하지 않는다.

```text
$daily-work-report
파일 위치: <정확한 폴더 경로>
파일명:
HANDOVER_A.md
HANDOVER_B.md
```

파일만 받았으면 간결한 분석 확인 후 `업무명과 보고서 작성 지시를 입력해주세요.`로 끝내고 대기한다.

## 다음 메시지와 후속 수정.

```text
(10/20) 일일 업무
1.2 AI 안전관리 VR 기능 수정 (진행중, 60%, 완료예정일:10/31)
표 없이 10~12줄, 개조식·명사형 종결로 작성해줘.
```

위 날짜·번호·진행률·완료예정일은 현재 날짜와 관계없이 그대로 유지한다.

```text
실제 완료된 항목 중심으로 10줄로 줄여줘.
```

선택 파일을 재사용한다. 미완료 제한을 숨기거나 실제 완료로 바꾸지 않는다. 업무명만 바꾸라는 요청도 새 업무와 원본의 관련성을 다시 확인한다.

## 최소 업무명만 받은 경우.

```text
(VTS Visualizer_Unity) VTS_Unity VR - 요구사항 확정 및 VR 기술 검증
```

STEP 1을 마친 같은 대화이면 작성 요청으로 해석한다. 번호·진행률·완료예정일을 만들어 넣지 않고 제목·내용 중심으로 작성한다. AISafetyVR 근거만 있다면 VTS 직접 구현·HMD 실기 성공을 주장하지 않는다. 실제로 확인한 요구사항·적용 가능성 검토와 기존 제품 검증을 구분한다.
