# 보고서 형식과 점검.

## 우선순위.

현재 사용자의 형식·분량·문체·저장 지시를 먼저 따른다. 그다음 사용자가 직전에 준 보고서 템플릿, 그다음 기본 양식 순이다. 일반 응답의 문장형 설명·마침표 규칙보다 보고서의 개조식·명사형 종결을 우선한다.

날짜·업무명·번호·상태·진행률·완료예정일은 원문 그대로 보존한다. 이름이 비슷해도 WebGL·AISafetyVR·VTS Unity를 바꾸지 않는다. 없는 메타데이터는 생성하지 않는다.

## 기본 10~12줄.

완전한 기본 양식을 요청했고 필요한 업무 헤더가 제공됐다면 다음 순서로 작성한다.

1. 날짜 한 줄.
2. `1. 주요 업무내용` 한 줄.
3. 공백 두 칸과 사용자 업무 헤더 한 줄.
4. 공백 네 칸과 `- `로 시작하는 상위 요약 한 줄.
5. 공백 여섯 칸과 `= `로 시작하는 세부 항목 6~8줄.

기본은 10~12개의 물리 줄이다. 빈 행을 넣지 않으며 파일 끝 개행은 없어도 되고 한 개여도 된다. 한 항목은 의미가 보존되는 범위에서 한 줄로 압축한다. 12줄이면 세부 8개, 11줄이면 7개, 10줄이면 6개다. 확정 근거가 모자라면 먼저 부족함을 밝히고 더 짧은 보고서나 추가 자료를 요청한다. 줄 수를 맞추려고 사실을 분할·반복·추측하지 않는다.

날짜가 없으면 Asia/Seoul의 확인한 현재 날짜를 사용할 수 있다. 번호·진행률·완료예정일이 없는 업무명만 받으면 가짜 값 없는 제목·내용 중심의 사용자 지정 형식을 사용한다. 기본 검사기의 번호 구조를 맞추려고 메타데이터를 만들어내지 않는다.

## 교체용 섹션.

전체 보고서의 1.1·1.2·1.3 중 1.2를 교체하라는 요청이면 1.2의 내용만 새로 작성한다. 다른 번호의 업무는 출력하거나 수정하지 않는다. 기본 보고서 모드에서는 날짜와 `1. 주요 업무내용`을 포함한다. `섹션 본문만`이면 날짜·상위 헤더를 생략하며 업무 헤더도 제외하라는 요청이면 본문만 출력한다. 일부 섹션·본문 출력은 custom 모드로 검사한다.

## 문체.

- 상위 요약은 하루 작업의 핵심을 아우르는 짧은 명사형 구절로 쓴다.
- 세부는 수행 내용과 산출 결과 중심으로 재구성한다. 원문 문장을 무작정 나열하지 않는다.
- 종결은 `구현`, `적용`, `반영`, `개선`, `수정`, `보정`, `검토`, `분석`, `설계`, `수립`, `작성`, `검증`, `완료`, `정리`, `연동`, `배포` 등을 사용한다.
- `~함`, `~했다`, `~한다`, `하였습니다`, `검토하고 있습니다`, `구현할 예정입니다` 등 문장형 종결과 근거 없는 과장을 피한다.
- 기술명·시나리오 번호·검증 수치는 근거가 있을 때 보존한다.
- 기본은 표·체크리스트·장식·장황한 해설 없이 복사 가능한 보고서 본문만 출력한다. 사용자 현재 지시가 별도 형식을 지정하면 그 형식을 따른다.

## 검사 범위.

출력 전 원본과 항목별로 사실·상태·시점·프로젝트·수치·미검증 제한을 직접 대조한다. 보고서 앞뒤에 출처·근거표·추가 조언을 붙이지 않는다. 사용자가 근거를 요청하면 별도 응답으로 제공한다.

`scripts/validate_report.py`는 기계적으로 확인 가능한 줄 수, 기본 구조, 정확한 업무 헤더, 표·장식, 명시적인 금지 종결형, 빈 행, UTF-8만 검사한다. 의미·수치 진위·명사형 문장의 품질·개인정보의 완전한 탐지를 보증하지 않는다.

custom 모드에는 기본 줄 수·번호·기호를 강제하지 않는다. 필요한 `--min-lines`·`--max-lines`와 `--expected-heading`만 지정한다. 검사기가 표·장식·일부 종결형을 금지하므로 사용자가 그런 표현을 명시적으로 요구한 형식은 기계 검사 범위를 벗어난다. 사용자의 현재 형식을 먼저 따르고 그 검사를 생략한 이유를 구분한다. 검증을 위해 보고서를 자동 저장하지 않는다. stdin이나 사용자가 명시적으로 저장한 파일을 사용한다.
