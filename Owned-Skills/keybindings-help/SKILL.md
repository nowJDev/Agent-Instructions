# 단축키 설정.

요청한 앱·입력 화면·키·동작을 정확히 연결하고 나머지 키맵을 보존한다.

## 입력과 앱 확인.

- 대상 앱과 버전, 터미널/IDE/데스크톱 구분, 키 조합, 원하는 동작과 적용 context를 확인한다.
- 사용자가 지정한 앱이 우선이다. Codex·VS Code·터미널 자체 요청을 Claude 설정 변경으로 대체하지 않는다.
- [현재 Claude 단축키 문서](https://code.claude.com/docs/en/keybindings)와 사용 중 버전의 액션·예약 키를 확인한다.
- 공식 문서 또는 설치된 앱에서 지원을 확인하지 못한 action/context 이름을 새로 만들지 않는다.
- Claude에서는 `/keybindings` 또는 현재 설정 루트로 실제 파일을 찾는다. 기본 위치는 `~/.claude/keybindings.json`이다.
- Codex 등 다른 앱은 그 앱의 현재 공식 설정 문서·UI를 확인한다. 지원하지 않으면 정확한 한계와 가능한 입력 방법을 안내한다.

## 현재 키맵과 변경 범위.

1. 대상 파일 전체를 읽어 `bindings` 배열의 context별 키 매핑과 충돌을 확인한다.
2. 요청한 기능이 `Chat` 입력인지 전역/대화상자/편집기 동작인지 구분한다.
3. 단일 키와 chord의 접두어 충돌, OS·터미널·IME가 가로채는 조합, 예약 키를 확인한다.
4. 기존 파일을 비공개 백업 위치에 보존하고 해시 또는 복사 결과를 확인한다.
5. 변경 전후의 해당 키·context·action만 명시한다. 같은 범위가 이미 승인됐다면 재확인을 요구하지 않는다.

## 최소 병합.

- 같은 context 블록의 요청 키만 수정하고 다른 키·context·알 수 없는 기존 필드를 유지한다.
- 같은 context가 여러 블록에 있으면 적용 순서와 중복 충돌을 먼저 확인하고 추측으로 배열 전체를 교체하지 않는다.
- 새 context가 필요할 때만 블록 하나를 추가한다. 해제는 현재 schema에서 지원하는 `null` 매핑을 사용한다.
- chord는 공식 키 표기와 순서를 쓰고 접두어의 기존 단축키에 주는 영향을 보존한다.
- JSON을 UTF-8로 저장하며 env·권한·hook·플러그인 설정을 함께 바꾸지 않는다.
- 실제 파일이 없으면 요청한 바인딩과 필수 구조만 생성한다. 다른 PC의 전체 키맵을 복사하지 않는다.

## 실패와 검증.

- 원본 파싱 실패는 먼저 원인과 위치를 보고한다. 빈 기본 파일로 덮어써 우회하지 않는다.
- 저장 후 JSON 파싱과 현재 공식 schema 검증을 하고 요청한 context/action만 달라졌는지 diff로 확인한다.
- [공식 schema](https://www.schemastore.org/claude-code-keybindings.json)는 현재 버전 지원 여부와 함께 대조한다.
- 가능하면 대상 앱의 실제 키 입력으로 전송·줄바꿈·chord를 확인한다. 메시지 전송 시험은 외부 전송 없이 안전한 화면에서 수행한다.
- 검증 실패 시 백업에서 해당 변경을 복구하고 잘못된 액션·단말 충돌·권한 문제를 구분한다.
- 입력 제어 도구가 없으면 파일 검증만 했음을 밝히고 정확한 수동 확인 동작을 남긴다.
- 결과에 앱·파일·변경 키·백업·파싱/schema 결과와 실제 키 입력 확인 여부를 보고한다.
