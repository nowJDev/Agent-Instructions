# 리뷰 진입점.

리뷰 요청은 수정·커밋·PR 게시·메시지 전송 권한이 아니다.

## 독립 실행의 공통 검토.

설치된 code-review가 있으면 전체 절차를 읽고 적용한다. 없어도 다음 공통 검토를 직접 수행한다.

1. 읽기 전용 진단이 기본이다. 적용 지침·요구사항·검증 명령을 확인하고 staged·unstaged·untracked 변경을 구분한다. Git 변경이 없어도 명시된 파일·증상은 현재 코드 진단으로 검토한다.
2. 변경 파일을 처음부터 끝까지 읽고 가용 검색 도구로 호출자·인터페이스·export·설정·fixture·테스트와 데이터 흐름을 추적한다.
3. PR은 base/head SHA를 확정하고 대상 SHA의 전체 본문을 읽는다. 워킹트리와 원격 PR의 다른 버전을 섞지 않는다. 범위 불일치면 올바른 자료를 확보하기 전 그 부분의 결론을 보류한다.
4. 정상 입력·null/빈 값·실패·재시도·동시성·권한 경계에서 계약을 확인하고 재현 조건과 사용자 영향을 입증한다. 테스트 통과만으로 결함 부재를 단정하지 않는다.
5. 필요한 최소 검사는 기존 권한 안에서만 실행한다. 설치·네트워크·데이터 변경이 필요하면 실행 범위를 확인한다. 자료/도구/검사 실패는 미검증으로 남긴다.
6. 심각도, 파일·줄, 재현 조건, 실제 영향, 근거, 최소 수정안을 보고한다. 확정 결함·선택 제안·미확인 의심을 구분하고 같은 근본 원인의 중복을 합친다.
7. 실제 검사 명령·결과·검토 SHA·읽지 못한 범위와 남은 위험을 남긴다. 비밀값·인증 헤더·개인 데이터는 값 대신 위치와 유형만 보고한다.

## 입력 확인.

1. 사용자가 준 PR URL·번호, 커밋·브랜치, 파일 또는 현재 변경 중 대상을 구분한다.
2. PR 번호만 있으면 현재 저장소의 remote로 소유자와 저장소를 확인한다. 다른 저장소를 추정하지 않는다.
3. 인자가 없고 현재 변경이 있으면 그 변경을 대상으로 한다. 변경이 없으면 리뷰할 기준을 확인한다.
4. 파일만 지정했으면 파일 전체를 읽되, 변경 리뷰인지 현재 코드 진단인지 결과에 명시한다.

## 도구와 범위 확정.

1. 로컬은 Git 상태·diff와 `rg`를 사용한다. PR은 실제 연결된 GitHub 읽기 도구 또는 기존 `gh`를 사용한다.
2. PR의 base·head SHA를 기록한다. 새 커밋이 생겼으면 기존 결과가 어느 SHA 기준인지 표시한다.
3. 원격 접근이 막히면 현재 코드 리뷰로 조용히 대체하지 않는다. 확보한 자료와 부족한 자료를 구분한다.
4. 로그·설정에서 실제 토큰이나 인증 헤더를 출력하지 않는다.

## 공통 검토 실행.

- 공통 절차로 변경 파일 전체·호출자·테스트를 읽고 재현 가능한 결함을 확인한다.
- 보안 집중 요청이면 설치된 security-review를 사용한다. 없으면 공격자가 통제하는 입력부터 인증·권한 검사와 위험 사용처까지 추적해 도달 조건·영향을 분석하고 비밀값 없이 보고한다. 실제 공격 실행으로 확대하지 않는다.
- 실제 앱 동작 확인이 요청되면 설치된 verify를 사용한다. 없으면 실행 권한과 환경을 확인하고 요청한 사용자 행동을 재현해 기대/실제 결과·오류를 비교한다. 핵심 흐름이 미재현이면 완료라고 하지 않는다.
- 단순화 제안은 결함과 구분한다. 리뷰 중 관련 없는 파일을 손대지 않는다.
- 사용자가 병렬 검토를 요구하지 않았다면 한 검토 흐름으로 충분하다.

## 실패 처리와 결과.

- 대상이 없으면 리뷰할 변경이 없다고 보고한다. 빈 diff를 승인 판정으로 바꾸지 않는다.
- 접근 실패·실행 불가·근거 부족은 미검증 범위로 남긴다.
- 공통 형식으로 결함, 위치, 재현 조건, 영향, 수행 검사와 한계를 출력한다.
- 게시·메시지·코드 수정·병합은 이 스킬에서 자동 실행하지 않는다.
- 사용자가 별도로 요청한 외부 작업은 구체적 결과와 대상을 확인한 뒤 해당 권한 안에서 수행한다.

PR 조회 방법은 [GitHub CLI PR 안내](https://cli.github.com/manual/gh_pr)를 참고하고 실제 가용 도구와 인증 상태를 확인한다.
