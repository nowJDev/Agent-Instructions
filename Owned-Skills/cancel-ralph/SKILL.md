# 현재 반복 취소.

## 입력.
- 취소할 작업·클라이언트·프로젝트·세션을 현재 대화나 명시된 식별자로 확인한다.
- 새 반복을 만들거나 취소 요청을 완료·커밋·전체 정리 권한으로 확대하지 않는다.

## 절차.
1. 현재 세션의 수동 반복이면 다음 반복을 예약하지 않고 멈춘다. 실행 중 도구는 지원되는 취소 API로 중지하고 마지막으로 확정된 반복·수정·검증 결과를 보존한다.
2. 실제 Claude Ralph 상태를 취소할 경우 현재 설치 버전의 상태 위치와 취소 기능을 확인한다. `.claude/ralph-loop.local.md`는 가능한 위치 예시이며 프로젝트 루트와 실제 경로를 검증한다. 상태가 없으면 해당 위치에 활성 상태 없음으로 보고한다.
3. 파일이 있으면 전체를 읽고 세션 ID·활성 여부·반복 번호를 확인한다. 실제 경로가 지정 프로젝트 내부에 있는지, symlink·junction으로 다른 위치를 가리키지 않는지 확인한다.
4. 다른 세션 소유라면 삭제하지 않는다. 현재 세션 식별을 확인할 수 없으면 모호한 대상을 지우지 말고 확인할 정보를 묻는다.
5. 현재 소유가 확인되고 사용자가 그 Ralph 취소를 요청한 경우에만 해당 상태 파일 하나를 제거한다. PowerShell이면 확인된 정확한 경로에 `Remove-Item -LiteralPath`를 사용하며 재귀·와일드카드는 쓰지 않는다.
6. 상태 파일 부재 또는 native 취소 완료 응답을 다시 확인한다. 자식 프로세스가 독립적으로 남았다면 해당 작업 소유 프로세스인지 확인한 뒤 지원되는 중지 방법만 사용한다.
7. 취소된 작업, 마지막 반복, 남은 프로세스·파일과 미완료 사항을 보고한다.

## 오류와 종료.
- 파일 잠금·권한 오류이면 임의 경로에서 삭제를 재시도하지 않는다. 관찰한 오류와 현재 상태를 보고한다.
- 상태 파일 손상은 소유권 증거가 아니다. 다른 세션 데이터·코드·Git 이력·트랜스크립트를 삭제하지 않는다.
- 도구 호출이 끝났다는 것과 반복 스케줄이 중지됐다는 것을 구분해 확인한다.

## 참고.
이 절차는 현재 작업의 반복만 중단하는 자체 작성 운영 지침이다. Claude의 이벤트·중단 처리 구조는 [공식 hooks 문서](https://code.claude.com/docs/en/hooks)를 확인한다. 다른 클라이언트에는 실제 지원되는 취소 기능만 적용한다.
