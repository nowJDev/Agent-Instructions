# 보안 검토.

## 검토 경계.
- 대상 저장소·변경 SHA·자산·공개 범위와 읽기 전용인지 수정까지인지 확인한다. `code-review`가 있으면 근거 수집에 사용한다. 없으면 Git 상태·대상 SHA·diff를 확인하고 변경 파일 전체·호출자·테스트를 직접 읽는다. 코드 검색에는 `rg`를 우선한다.
- 보호할 자산과 공격자가 통제할 수 있는 입력을 구분한다. HTTP·파일·환경·다른 프로세스 인자·LLM 출력도 누가 쓸 수 있는지 확인한다.
- 실제 서비스 공격·파괴적 재현·외부 스캐너 전송은 이 스킬의 기본 동작이 아니다. 허용된 로컬 자료와 안전한 재현으로 시작한다.

## 조사 절차.
1. 진입점부터 인증·권한 검사·정규화·검증·위험한 사용처까지 입력 흐름을 추적하고 관련 파일 전체·호출자를 읽는다.
2. 사용자/테넌트 경계, 객체 소유권, SQL·shell·HTML·파일 경로·외부 URL·업로드·토큰·로그의 신뢰 경계를 확인한다.
3. 소스·설정·diff의 비밀 후보는 값 대신 파일·줄·유형만 기록한다. 실제 키·인증 헤더·개인 데이터를 답변이나 외부 도구에 넣지 않는다.
4. 삭제·이동·덮어쓰기는 정규화한 최종 경로·허용 루트·그 아래 깊이·조작 전 확인한 소유권을 함께 본다. 경로 모양만 맞거나 파일이 있다고 정당한 소유로 간주하지 않는다.
5. 인증 누락·권한 상승·다른 테넌트 접근·주입·SSRF·경로 탈출·민감정보 노출·무제한 자원 사용을 실제 도달 경로와 대조한다.
6. 의존성은 사용 중인 lockfile·버전·실행 경로와 공식 보안 공지를 확인한다. 감사 등급만으로 실제 악용 가능성이나 모든 안전을 단정하지 않는다.
7. 필요하면 허용된 격리 fixture에서 정상·공격성 입력을 비교한다. 실제 사용자 데이터 삭제·프로덕션 요청·강제 의존성 업그레이드는 수행하지 않는다.
8. 발견마다 공격 전제→제어 입력→검사 우회→위험 사용처→영향을 증거로 연결한다. 경로를 입증하지 못한 의심은 미확인으로 구분한다.
9. 최소 완화와 확인할 회귀를 제안한다. 수정 요청이 유효할 때만 원인에 가까운 경계에서 변경하고 관련 검증을 실행한다.

## 실패와 보고.
- 접근할 수 없는 코드·환경·버전이나 공식 공지 조회 실패는 검토 공백으로 남긴다.
- 심각도와 신뢰도를 나눠 파일·줄, 필요한 권한·입력, 영향, 재현 근거, 최소 완화·검증 방법을 보고한다.
- 공격용 payload는 로컬 재현에 필요한 범위만 쓰며 실제 비밀 값을 예제로 쓰지 않는다.
- 결함을 찾지 못했으면 조사 범위 안에서 발견하지 못했다고 한다. 보안이 보장됐다거나 외부 감사가 완료됐다고 표현하지 않는다.
- 사용자 요청 없는 PR 게시·메시지·키 교체·정책 변경·의존성 설치로 검토 범위를 넓히지 않는다.
