# 클라이언트 설정 변경.

요청한 앱·범위·개별 키만 변경하고 현재 schema와 실제 적용 결과를 확인한다.

## 입력과 가용 기능 확인.

- 대상 클라이언트·버전·프로젝트·사용자/프로젝트/개인 로컬 범위와 원하는 전후 동작을 확인한다.
- 사용자가 지정한 앱이 우선이다. 신뢰할 수 있는 현재 앱 정보도 없으면 한 번 확인한다.
- 현재 공식 문서·schema와 노출 도구를 확인한다. Claude 설정을 Codex에 그대로 복사하지 않는다.
- Claude는 [설정 파일·우선순위 문서](https://code.claude.com/docs/en/settings)를 읽어 실제 적용 파일을 확인한다.
- Codex는 [설정 참조](https://developers.openai.com/codex/config-reference)를 읽고 실제 앱의 지원 파일·키·이벤트를 확인한다.
- 1회성 작업에는 영구 hook을 만들지 않는다. 반복 동작도 현재 앱의 기본 기능·hook·예약 중 요청에 맞는 지원 기능을 고른다.
- 진단만 요청됐으면 읽기와 원인 보고에 한정한다. MCP·플러그인 설치나 권한 완화로 범위를 넓히지 않는다.

## 현재 설정 조사.

1. 대상 파일 전체와 적용 범위를 읽되 비밀값·인증 헤더·env 원문을 도구 출력에 노출하지 않는다.
2. 상위·개인·관리 설정의 우선순위와 강제 제약, symlink·동기화 원본 여부를 확인한다.
3. 유효한 원본 저장소가 있으면 덮어쓰기 위험을 확인하고 승인 범위의 원본·적용본을 일관되게 다룬다.
4. 기존 파일을 비공개 위치에 백업하고 이번에 바뀔 경로·키·의미만 짧게 정리한다.
5. 원본이 파싱되지 않거나 실제 적용 위치가 모호하면 해당 변경을 멈추고 원인을 먼저 해결한다.

## 개별 병합과 실행 경계.

- Claude Code에서 예를 들어 `DEBUG=true` 요청은 해당 범위의 `env.DEBUG`만 변경하고 나머지 env·hook·권한을 유지한다.
- 객체는 요청한 개별 키를 병합한다. 배열은 항목의 의미·실행 순서·중복을 확인하고 대상 항목만 추가/수정한다.
- hook은 같은 matcher라는 이유만으로 삭제·교체하지 않는다. 이벤트·matcher·실제 명령·조건·순서를 함께 비교한다.
- hook 명령의 인용·셸·경로·시간 제한·실패 동작과 어떤 데이터가 어디로 전달되는지 확인한다.
- 외부 전송 hook은 요청한 목적지·내용·트리거 범위만 허용한다. 실제 메시지 전송은 별도 명시된 범위에서만 검증한다.
- 권한은 필요한 좁은 패턴만 다루고 전체 허용·sandbox 해제·관리 정책 우회를 덧붙이지 않는다.
- 비밀값은 환경변수/안전한 저장소 참조를 사용한다. 샘플 설정이나 커밋에 실제 토큰을 쓰지 않는다.
- 기존 지원 필드·주석·서식을 가능한 보존한다. 앱이 지원하지 않는 키와 이벤트를 지어내지 않는다.

## 실패와 결과 검증.

- UTF-8 저장 전후 JSON/TOML 파싱과 현재 공식 schema 검증을 한다. 파서 성공만으로 적용됐다고 단정하지 않는다.
- diff에서 요청한 키와 관련 항목만 바뀌었는지 확인하고 비밀값을 가린 변경 요약을 만든다.
- 앱의 안전한 설정 조회·진단 또는 부작용 없는 이벤트로 검증한다. 필요 시 재시작/새 세션 조건을 명시한다.
- hook은 성공·비정상 입력·실패 경로를 격리된 안전한 입력으로 확인하고 로그에 시크릿이 남지 않는지 본다.
- 검증 실패 시 백업으로 이번 변경만 복구하고 실패 원인·영향 범위·남은 확인을 보고한다.
- 결과에 앱·범위·변경 파일/키·백업·파싱/schema 결과·실제 적용 검증과 미검증 항목을 구분한다.
