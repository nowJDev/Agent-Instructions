# 검증 가능한 Ralph 반복.

## 입력과 환경.
- 작업 목표·수정 범위·완료를 판정할 명령·최대 반복 횟수를 확인한다. 완료 문구만 있고 검증 기준이 없으면 먼저 기준을 정한다.
- 호스트와 실제 Ralph 플러그인·Stop hook 지원을 확인한다. Codex에서 Claude 명령이나 hook이 자동 작동한다고 가정하지 않는다.
- 구현 작업은 설치된 design-driven-delivery가 있으면 따른다. 없으면 요구사항·영향 파일을 조사하고 승인된 설계와 계획 안에서 최소 변경·실패 재현·회귀 검증·전체 변경 리뷰를 수행한다. 이미 승인된 범위를 다시 승인받지 않는다.

## 실행.
1. 인자의 작업 본문·최대 횟수·완료 신호를 구분해 파싱한다. Codex의 대체 반복에서는 양의 유한 횟수만 사용한다. 0·음수·소수·문자열이면 시작하지 않고 양의 한계를 정한다.
2. 실제 Claude Ralph 실행을 요청했고 설치된 명령·hook이 확인됐으면 현재 플러그인의 도움말·원본을 읽고 명시된 프로젝트·세션 범위에서만 호출한다. 설치나 전역 hooks 변경은 별도 요청이다.
3. Codex에서는 Claude의 자동 Stop 재주입이 작동한다고 가정하지 않는다. 현재 세션의 유한 반복 요청이면 설치된 loop를 사용한다. 없으면 현재 턴에서 한 번에 하나씩 실행하고 시도 번호·결과를 기록하며 정해진 횟수/기한 안에서만 재시도한다. 대기는 60초 이내로 나누고 이전 호출이 끝나기 전 다음 호출을 시작하지 않는다. 백그라운드 예약이나 새 작업을 임의 생성하지 않는다.
4. 매 반복에서 현재 diff·이전 실패를 확인하고 한 가지 근본 원인을 고친 뒤 정해진 검증을 실행한다. 같은 실패를 진전 없이 반복하면 원인을 재조사하고 한계·막힘을 보고한다.
5. 성공 조건을 실제 출력·종료 코드·관찰 증거와 대조한다. 완료 문구는 조건이 참일 때만 출력한다. 태그를 출력해 실행 실패를 감추지 않는다.
6. 성공, 횟수 소진, 사용자 취소, 새로운 승인·정보가 필요한 상태 중 하나가 되면 중단하고 현재 결과를 남긴다.

## 실패와 결과.
- 반복 번호, 수정 파일·검증 결과·다음 원인 가설을 짧게 기록한다. 기존 사용자 변경은 보존한다.
- 사용자 중단은 완료 신호보다 우선한다. 설치된 cancel-ralph가 있으면 사용한다. 없어도 다음 반복을 멈추고 지원되는 취소 도구로 자체 작업만 중지한다. 현재 호출을 취소할 수 없으면 그 상태를 알리고 추가 호출하지 않는다.
- Claude 상태 파일을 제거해야 하면 지정 프로젝트의 실제 루트·정확한 상태 파일 경로·session_id·활성 여부를 전체 읽어 확인한다. symlink/junction 해석 후 프로젝트 내부의 현재 세션 소유 파일 하나만 삭제하고 부재를 검증한다. 다른 세션이거나 소유권을 모르면 삭제하지 않고 확인한다. 와일드카드·재귀 삭제와 다른 작업 파일 정리는 하지 않는다.
- 최대 횟수에 도달했다면 성공으로 보고하지 않는다. 완료·취소·한계 도달·막힘을 구분한다.
- Claude 상태 파일을 만들기만 하고 실제 hook이 실행되는 것처럼 설명하지 않는다.

## 참고.
[공식 Ralph 플러그인 안내](https://github.com/anthropics/claude-plugins-official/tree/main/plugins/ralph-loop)는 설치된 Claude 런타임을 확인할 때 참고한다. 무제한 기본값을 Codex 기본 동작으로 가져오지 않는다. 문서에 도구가 적혀 있다는 사실은 현재 사용 가능하거나 실행 권한이 있다는 증거가 아니다.
