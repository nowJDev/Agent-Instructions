# Claude 뉴스.

공식 원문을 조회해 한국어로 요약한다. 조회만 요청받았으면 설치·업데이트·설정을 변경하지 않는다.
조회 전에 현재 클라이언트의 도구와 인증 상태를 확인한다. 이 파일만으로 입력 해석·선택·실패 처리를 수행한다.
릴리스 출처는 [공식 Claude Code 릴리스](https://github.com/anthropics/claude-code/releases)와 [GitHub 릴리스 API 안내](https://docs.github.com/en/rest/releases/releases)다.

## 입력과 실행 환경.

- 사용자 인자가 양의 정수면 해당 숫자만큼 유효한 릴리스를 선택한다. 0·음수·해석 불가 인자는 확인한다.
- 버전 인자면 `v` 유무를 정규화해 정확히 일치하는 태그만 찾고 다른 최신 버전으로 대체하지 않는다.
- 인자가 없으면 아래 기본 선택 규칙을 쓴다. 사용자가 지정한 기간·개수는 우선한다.
- 현재 시각·시간대를 확인해 조회 시점과 10일 경계를 고정한다.
- 가용 GitHub 릴리스 도구를 우선 확인한다. 없으면 공식 GitHub REST API 또는 공식 릴리스 페이지를 읽는다.
- 뉴스는 가용 웹 읽기 도구로 [Anthropic 공식 뉴스](https://www.anthropic.com/news)를 확인한다.
- Codex에서 `WebFetch`·`mcp__github__list_releases`·`$ARGUMENTS`가 있다고 가정하지 않고 실제 도구와 사용자 입력으로 대체한다.

## 조회와 선택.

1. `anthropics/claude-code`의 최근 릴리스와 body·태그·발행일·원문 URL을 가져온다.
2. 빈 body는 제외하고, 중복 태그를 제거한다. 날짜는 발행일 기준이며 모르면 날짜 미확인으로 표시한다.
3. 기본은 최근 10개를 시작점으로 10일 이내를 고른다. 경계가 페이지 밖이면 추가 페이지를 확인한다.
4. 10일 이내가 5개 미만이면 이전 유효 릴리스를 최신순으로 보충해 5개를 채운다. 존재하는 수가 적으면 그 수를 알린다.
5. 10일 이내가 5개 초과면 전부 표시한다. 기본을 최대 5개로 잘라내지 않는다.
6. 숫자 모드도 빈 body를 제외한 개수를 채우도록 추가 조회한다. 특정 버전 모드는 그 릴리스만 출력한다.
7. 뉴스는 모델·제품·개발자 기능을 고르고 정책·투자·채용 등은 제외한다. 기본은 10일 우선, 부족하면 이전 소식으로 5개까지 보충한다.
8. 10일 이내는 `[NEW]`, 보충한 이전 항목은 `[최근]`으로 구분한다. 뉴스가 없으면 그 사실을 짧게 알린다.

## 출력과 후속 설명.

- 뉴스는 A1·A2, 릴리스의 새 기능·주요 변경은 1·2로 전체 릴리스에 걸쳐 연속 번호를 붙인다.
- Added는 새 기능, 사용자 체감이 큰 Changed·Removed·Deprecated는 주요 변경으로 설명한다.
- Fixed와 나머지 개선은 원문 항목을 중복 계산하지 않고 버그 수정·기타 개선 건수로 묶는다.
- 버전·발행일·출처 링크를 각 결과에 붙이고 Windows/Git Bash 관련 항목은 `[Windows]`로 표시한다.
- 기술 용어는 유지하고 번호별 후속 설명에서도 같은 버전·원문을 사용한다.

## 실패와 결과 증거.

- 뉴스 조회 실패는 표시하고 릴리스 조회를 계속한다. 조회 실패를 소식 없음으로 표현하지 않는다.
- API 제한·인증·버전 부재는 원인과 확인 범위를 보고하며 다른 공개 공식 경로를 확인한다.
- 모든 경로가 실패하면 최신 내용을 지어내지 않고 재시도에 필요한 접근 조건을 알린다.
- 최종 결과에 조회 시점·선택 기준·선택 개수·누락/실패·공식 링크를 남긴다.
- 빈 body 제외와 지정 버전 일치, 기본 10일/5개 규칙을 결과와 대조한 후 완료한다.
