# 프로젝트 지침 초기화.

확인된 프로젝트 구조·명령·경계만 문서화하고 기존 사용자 규칙을 보존한다.

## 입력과 대상 확인.

- 프로젝트 루트·대상 클라이언트·출력 파일·초기화 범위를 현재 요청과 환경에서 확인한다.
- 사용자가 명시한 파일명이 우선이다. 파일 미지정이면 Claude Code는 `CLAUDE.md`, Codex는 `AGENTS.md`를 기준으로 한다.
- CLI·IDE·앱 중 실제 대상과 버전을 확인한다. 다른 앱의 자동 로딩 방식을 그대로 가정하지 않는다.
- 적용되는 상위·하위 지침과 기존 대상 파일을 전체 읽고 개인 예외·프로젝트 계약을 파악한다.
- 출력은 현재 프로젝트 안의 지정 문서다. 전역 지침·개인 설정·다른 앱 파일을 함께 바꾸지 않는다.
- 기존 문서를 초기화하라는 말만으로 삭제하지 않는다. 승인 범위 안에서 유효 규칙을 보존해 병합한다.

## 코드베이스 조사.

1. `rg --files` 또는 가용 파일 탐색 도구로 소스·진입점·테스트·설정·README 위치를 파악한다.
2. 생성물·의존성 폴더를 제외하고 관련 manifest·빌드 스크립트·CI·주요 진입 파일을 전체 읽는다.
3. 실제 사용 중인 언어·실행 구조·테스트 명령·배포 경계는 파일 경로와 함께 근거를 적는다.
4. 코드베이스가 크면 요청 범위의 대표 경로만 확인하고 조사하지 못한 부분을 표시한다.
5. 개인 설정·`.env`·키 파일을 원문으로 읽거나 지침에 복사하지 않는다. 필요한 변수 이름만 확인한다.
6. 명령과 파일 관계가 모순이면 원인을 확인한다. 보편적인 관례로 빈칸을 채우지 않는다.

## 최소 지침 작성.

- 프로젝트 목적, 주요 디렉터리 역할, 개발·빌드·테스트 명령, 수정 시 지켜야 할 핵심 경계를 적는다.
- 검증 명령은 실행 위치·필수 전제와 출처를 함께 쓴다. 실제 미실행이면 미실행이라고 적는다.
- 사용자 선호·전역 정책을 중복 복사하지 않고 프로젝트에서 필요한 차이만 남긴다.
- 폴더 한정 상세 규칙은 기존 규칙 구조를 따른다. 승인 없이 새 문서 체계를 넓히지 않는다.
- 개인 절대 경로·비밀값·내부 주소를 공개 추적 문서에 넣지 않는다. 상대 경로와 변수 참조를 쓴다.
- 기존 규칙과 충돌하는 부분은 근거를 확인해 수정하며 관련 없는 내용은 덮어쓰지 않는다.

## 실패와 결과 검증.

- 루트·대상 앱·기존 계약이 불명확하면 해당 결정을 확인하고 독립적인 조사만 계속한다.
- 설치 도구·네트워크·권한이 없어 확인할 수 없는 명령은 추정하지 않고 전제와 미검증 상태를 적는다.
- UTF-8로 저장한 파일을 재읽고 지침의 경로·명령을 실제 코드/CI와 대조한다.
- 문서의 로컬 링크가 존재하고 기존 개인 규칙·보호 파일이 보존됐는지 diff로 확인한다.
- 자동 로딩은 새 세션 또는 공식 지원 확인 수단으로 검증해야 한다. 파일 생성만으로 로딩 성공을 주장하지 않는다.
- 결과에 생성/수정 경로, 핵심 반영 근거, 실행한 검증과 미실행 검증을 구분해 보고한다.
- Codex 지침 계층이 불명확하면 [공식 AGENTS.md 안내](https://developers.openai.com/codex/guides/agents-md)를 확인한다.
