# 세션 기록 정리.

요청한 클라이언트·프로젝트·세션만 처리한다. 세션 목록 조회는 삭제 권한이 아니다.

## 입력과 클라이언트 확인.

- 현재 프로젝트의 실제 루트, 요청한 클라이언트, 선택 세션 ID와 보관/삭제 의도를 확인한다.
- 사용자 지정 대상이 우선이다. 미지정이면 신뢰할 수 있는 현재 앱 정보를 쓰고 판별 불가할 때 한 번 확인한다.
- 설치 목록이나 모델 이름으로 Claude Code·Codex를 추정하지 않는다.
- 현재 버전의 공식 세션 목록·보관·삭제 기능과 실제 가용 도구를 먼저 확인한다.
- Codex task 조회 기능은 대화 저장 파일과 다를 수 있다. 조회 권한을 task 생성·메시지 전송 권한으로 확대하지 않는다.
- Claude의 `.claude/projects` 규칙을 Codex에 대입하지 않는다. 설정된 사용자 홈·저장 루트를 실제 환경에서 확인한다.

## 목록과 대상 선택.

1. 쓰기 작업 전에 현재 프로젝트 세션만 나열한다. ID·시각·짧은 제목·활성 여부·확인된 저장 위치를 표시한다.
2. 대화 전체나 인증 정보를 출력하지 않고 프로젝트 연결과 식별에 필요한 메타데이터만 읽는다.
3. 명시적으로 선택된 ID가 없으면 목록을 보여주고 선택을 받는다. 제목이나 오래됐다는 이유로 임의 선택하지 않는다.
4. 활성 세션과 현재 대화는 제외한다. 사용 중인지 확인할 수 없으면 삭제하지 않는다.
5. 정확한 ID·프로젝트·처리 종류·대상 경로를 짧게 명시한다. 이미 같은 범위가 승인됐다면 재승인받지 않는다.

## 보관 또는 개별 삭제.

- resume 목록 정리가 목적이면 공식 보관 기능으로 충족하는지 먼저 확인하고 그 차이를 설명한다.
- 영구 삭제가 명시된 경우에는 지원되는 삭제 기능을 사용하고 복구 가능 여부를 알린다.
- 파일을 직접 다뤄야 하면 선택 ID와 저장 메타데이터·프로젝트 연결·실제 경로가 모두 일치하는지 검증한다.
- symlink·junction을 해석한 최종 경로가 확인된 저장 루트 안에 있고 정확한 개별 파일인지 확인한다.
- 선택 파일을 비공개 백업 위치에 복사해 크기·해시를 확인하고 복구 경로를 기록한 뒤 처리한다.
- Windows 파일 처리는 PowerShell 한 셸에서 `-LiteralPath`로 개별 파일만 삭제한다.
- 전체 폴더·와일드카드·재귀 삭제는 하지 않는다. 인덱스 DB나 연결 파일을 추측으로 수정하지 않는다.
- 공식 기능이 없고 연결된 인덱스·동시 쓰기 영향이 불명확하면 파일 삭제를 멈추고 지원되는 보관 방법을 안내한다.

## 실패와 결과 증거.

- ID·경로·프로젝트 불일치, 백업 실패, 사용 중 파일, 권한 오류는 해당 대상을 중단하고 원인을 보고한다.
- 일부 성공이면 성공·실패 ID를 구분한다. 다른 세션까지 지워 재시도하지 않는다.
- 공식 목록을 다시 조회해 선택 대상의 상태를 확인하고 원본/백업의 존재 여부를 대조한다.
- resume 목록을 실제 확인하지 못했다면 파일 처리 결과와 목록 반영 미검증을 구분한다.
- 결과에는 클라이언트·프로젝트·대상 ID·처리 방식·검증 결과·백업/복구 위치만 남긴다.
- 원문 세션과 백업은 개인 자료로 유지하며 커밋·외부 업로드하지 않는다.
